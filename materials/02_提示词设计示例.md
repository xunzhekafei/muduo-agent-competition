## 示例 1：系统提示词 —— 把「问答机器人」变成「学习导师」

**原文**（`backend/app/agent/prompts.py`，节选）：

```text
你是「木铎」——一名 AI 学习导师 Agent，服务于大学生和考研学生。
## 你的目标
帮学生把「记笔记 → 理解 → 记住 → 检验」串成完整的学习闭环。
你不是问答机器人：用户说一句模糊的话，你要自己判断该做什么，并把它做完。
## 工作方式
1. 先查再答。凡是涉及用户自己的数据……必须先调用工具获取，绝不凭猜测回答。
2. 一次尽量做完。典型链路是：list_courses → search_notes → get_overview / list_due_cards……
4. 给出可执行的结果。回答要落到"做什么、做多久、为什么"……
```

**设计意图**：
- 用「你不是问答机器人」一句话锚定行为模式，避免模型退化成通用聊天
- 「先查再答」把工具调用变成硬约束，从源头压制幻觉（不编造笔记和数字）
- 「一次尽量做完」规定多步执行，而不是每一步都反问用户

**实测效果**：用户只说「帮我安排今天的复习」，Agent 自主完成 3 次工具调用并给出 40 分钟、
精确到卡片的计划，中间没有反问一句废话。

## 示例 2：费曼评估 —— 用「评分档位 + 输出结构」约束评估质量

**原文**（`backend/app/agent/schemas.py`，`evaluate_feynman` 工具描述）：

```text
对费曼会话打分评估并结束会话。
score 为 0-100（90+讲得透彻能教别人；70-89基本正确有小漏洞；
50-69框架对但含糊；<50有概念性错误）。
feedback 先肯定讲对的部分，再指出 1-2 个最大漏洞和改进建议。
```

**设计意图**：
- 给出**可锚定的分数档位**，避免模型给出「85 分」却不说人话的随机评分
- 固定反馈结构（先肯定 → 1-2 个漏洞 → 改进建议），保证评估可执行且不打击学习积极性
- 限制「1-2 个」漏洞，防止一次打击面过大

## 示例 3：SM-2 评级 —— 用反例提示防止「虚假好评」

**原文**（`backend/app/agent/schemas.py`，`schedule_review` 工具描述）：

```text
记录一次记忆卡复习结果，并按 SM-2 间隔重复算法排下次复习时间。
grade 要按实际表现诚实评级：again 完全忘了/答错（间隔重置）、
hard 答对但吃力、good 答对较顺、easy 秒答非常熟。
把'其实忘了'标成 good 会让卡片排得太远、真正忘掉，宁可标 again。
```

**设计意图**：
- 四个档位各配一个行为锚点，消除「良好」和「轻松」之间的模糊地带
- 显式写出**错误行为的后果**（标成 good → 排太远 → 真忘掉），比单纯下指令更有效
- 「宁可标 again」给出冲突时的默认选择，保证 SM-2 排期数据质量

## 示例 4：工具触发条件 —— 让模型选对工具（RAG vs 笔记发现）

**原文**（`backend/app/agent/schemas.py`）：

```text
search_notes：按关键词检索用户的笔记，返回标题和匹配摘要。
  ……只返回摘要（约200字），若需要完整内容请接着调用 get_note。
search_knowledge：知识库语义检索：从用户笔记/导入资料的分块库里，
  找与问题最相关的原文片段。回答'X 是什么''资料里怎么解释 Y'
  这类需要原文依据的问题时优先使用；与 search_notes（笔记级发现）互补。
```

**设计意图**：
- 两个易混淆工具都写明「什么时候用 / 和另一个的区别」——工具 description 本身就是提示词
- 说明返回粒度（摘要 vs 原文片段），引导模型串联调用（先发现、再精读）
- 实测中 Agent 对「讲讲死锁」正确走了「知识库检索 → 检索笔记 → 读取笔记」三步链路
