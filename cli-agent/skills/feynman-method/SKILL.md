# 费曼学习法（Feynman Technique）

核心思想：**能把一个概念用简单的话讲清楚，才算真正理解**。
讲解中的卡壳、含糊、堆术语的地方，就是理解的漏洞。

## 触发时机

- 学习者说「我学完了 X」「帮我检验一下我懂不懂 X」「我想练练讲解」
- 复习计划里安排了「输出/讲解」环节
- 你发现学习者回答问题时堆砌术语但没有自己的话

## 标准流程（三步，对应三个工具）

### 1. 开始会话 —— `run_feynman(concept_name, explanation, note_id)`

- `concept_name`：要讲解的概念（如「进程与线程的区别」）
- `explanation`：**学习者自己的讲解原话**。学习者没讲就先要，不要替他编——费曼的价值在于暴露他自己的理解
- `note_id`：相关笔记 ID（可选，有则关联；先用 search_notes 找）

### 2. 追问堵漏 —— `feynman_add_question(session_id, question)`

对照评估四维度找漏洞，**一次只追一个问题**，小而具体：

| 维度 | 看什么 | 追问示例 |
|------|--------|---------|
| 准确性 | 有没有说错 | 「你说 X 一定会 Y，那什么情况下不会？」 |
| 结构 | 有没有因果链 | 「为什么 A 会导致 B？中间那一步是什么？」 |
| 通俗 | 是否只在堆术语 | 「能不用『并发』这个词，给我讲讲吗？」 |
| 通俗 | 能否打比方 | 「能举个生活中的例子吗？」 |

先问漏洞最大的维度；学习者答不上来时，降一档问更基础的问题，不要连续追问同一处超过 2 次。

### 3. 评估收尾 —— `evaluate_feynman(session_id, score, feedback, follow_up_questions)`

- `score`：0-100。参考档位：90+ 讲得透彻能教别人；70-89 基本正确有小漏洞；50-69 框架对但含糊；<50 有概念性错误
- `feedback`：先肯定讲对了什么，再指出 1-2 个最大漏洞，最后给一条可执行的改进建议
- `follow_up_questions`：漏洞对应的补强问题列表（如 ["用一句话解释页表的作用"]），供下次复习用

## 原则

- 讲解内容以学习者原话为准，评估针对讲解、不针对人
- 不要一次抛出所有漏洞；抓大放小
- 评估完成后提醒学习者：把 follow_up_questions 里的问题加入复习计划（generate_memory_cards / schedule_review）
