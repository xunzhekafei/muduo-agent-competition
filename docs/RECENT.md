## 〇、产品闭环

两条主干学习链路，所有功能围绕它们展开：

```
链路 A（课堂）：速记(时间流/时间树) → 我的笔记 → 思考 → 记忆 → 费曼 → 闭环
链路 B（自学）：资源转笔记 → 我的笔记 → 思考 → 记忆 → 费曼 → 闭环

支撑层：学习中枢 + 共享社区
```

当前两条链路的基础代码都已存在，策略是**在现有代码上逐环节打磨，不重写、不打散**。

## 三、阶段 1：三大核心入口（第 1-2 周）

### 1-1 我的笔记

**当前状态**：TipTap 编辑器已引入但交互细节粗糙；`note_type` 字段已加但前端未展示来源分组；右键菜单有基础功能但缺少分享和导出。

**目标**：笔记的编辑、浏览、组织体验达到"好用"水平。

| # | 任务 | 具体做什么 | 验收方式 |
|---|------|-----------|---------|
| 1 | 编辑器稳定 | 测试 TipTap ↔ note_blocks 转换的边界情况：空段落保存/加载、表格增删行列后保存、特殊字符（LaTeX、代码块）的正确渲染 | 创建各种类型内容的笔记 → 保存 → 刷新 → 内容无损 |
| 2 | 来源分类展示 | 修改 `NoteManagement.jsx`：目录树按 `note_type` 分组（课堂速记/资源导入/我的笔记/思考记录），每篇笔记标题旁显示来源标签 | 打开我的笔记 → 看到四个分组 → 笔记有来源标签 |
| 3 | 右键菜单 | 增加"分享到社区"（调 `POST /community/assets`）和"导出 Markdown"（前端生成 .md 下载）；已有的重命名/归档/删除保持正常 | 右键 → 四个菜单项均可点击并生效 |
| 4 | 搜索高亮 | 搜索结果列表中，匹配的关键词用 `<mark>` 标签黄色高亮 | 搜索"进程调度"→ 匹配文字标黄 |
| 5 | 空状态引导 | 新用户没有任何笔记时，显示引导卡片："创建第一篇笔记"按钮 → 跳转资源转笔记 或 速记模式 | 清空数据库 → 打开我的笔记 → 看到引导卡片 |

### 1-2 资源转笔记

**当前状态**：上传/解析/保存链路已有，文件删除和网页解析已修复，多模态整合已改进。

**目标**：全流程无 Bug，错误处理完善。

| # | 任务 | 具体做什么 | 验收方式 |
|---|------|-----------|---------|
| 1 | 全流程走通 | 逐环节手动测试 PDF 上传→解析→AI 生成→保存；网页链接→解析→保存；PDF+网页 同时上传→整合输出 | 每种场景完整走通，无报错 |
| 2 | 进度提示细化 | 后端 `service.py` 的 phase 文字改为中文具体描述：如"正在读取 PDF 第 3/10 页""AI 正在提取核心概念（已生成 500 字符）" | 解析过程中进度条下方显示具体阶段文字 |
| 3 | 错误处理 | 上传文件 >100MB → 提示文件过大；网页无法访问 → 提示链接不可达并给出具体原因；解析超时（5 分钟）→ 提示超时并提供重试 | 每种错误有明确中文提示 + 重试按钮 |

### 1-3 速记模式（时间流速记）

**当前状态**：已重写为真实录音 + 语音识别 + AI 整合，基础流程可走。

**目标**：录音和识别体验稳定，AI 生成笔记质量达到可用。

| # | 任务 | 具体做什么 | 验收方式 |
|---|------|-----------|---------|
| 1 | 录音稳定性 | 处理麦克风权限拒绝（显示引导弹窗："请在浏览器设置中允许麦克风访问"）；处理录音中断（浏览器切后台/锁屏） | 拒绝权限 → 看到引导提示；切后台 → 录音自动暂停并提示 |
| 2 | 语音识别适配 | 测试不同语速（快/慢）、不同环境（安静/嘈杂）的识别效果；SpeechRecognition 不可用时（Safari/Firefox）显示提示"请使用 Chrome 或 Edge 浏览器" | Chrome 下正常识别；Firefox 下显示浏览器提示 |
| 3 | AI 生成质量 | 调优 `/notes/ai-generate` 的 system prompt：确保标题层级正确（# → ## → 1. 列表）、不编造内容、输出长度 500-2000 字 | 录制 2 分钟内容 → AI 生成笔记 → 层级合理、无编造 |
| 4 | 手动编辑转写 | 语音识别出的文字支持用户点击编辑修正（识别不可能 100% 准确） | 点击转写文字 → 可编辑 → 修改后影响 AI 生成的输入 |

### 1-4 速记模式（时间树速记）

**当前状态**：前端 `TimeTreeNotes.jsx`（355 行）已有完整 UI——树形节点结构、展开/折叠、节点详情弹窗、导出到我的笔记。但数据全为 Mock（`MOCK_NODES` 12 个固定节点 + `EXPORT_DETAILS` 写死的节点内容）。无对应后端模块。

**目标**：用户可在时间树页面自由增删节点、编辑内容、从树形结构导出为结构化笔记。

| # | 任务 | 具体做什么 | 验收方式 |
|---|------|-----------|---------|
| 1 | 去掉 Mock 数据 | 删掉 `MOCK_NODES` 和 `EXPORT_DETAILS` 常量；改为从后端加载笔记树（用 `GET /notes` 获取笔记列表，通过 `note_type="quick_timetree"` + `metadata.parentId` 构建树结构） | 刷新页面 → 数据来自后端而非硬编码 |
| 2 | 新增树节点 | 在已有节点下点击"+"→ 弹出输入框 → 输入标题 → 创建新节点（调 `create_note`，`note_type="quick_timetree"`，`metadata` 中存 `parentId`） | 新增子节点 → 出现在父节点下方 → 刷新仍在 |
| 3 | 编辑节点内容 | 点击节点 → 弹出编辑面板（当前已有弹窗 UI，需改为真实保存）→ 编辑内容 → 保存（调 `update_note` 或 `saveNoteBlocks`） | 编辑后保存 → 关闭再打开 → 内容已更新 |
| 4 | 删除节点 | 节点右键菜单或弹窗内增加「删除」按钮 → 确认后删除节点及所有子节点（调 `DELETE /notes/{id}`） | 删除 → 节点从树中消失 |
| 5 | 导出到笔记 | 已有的"导出笔记"按钮保留，改为读取树上所有节点的真实内容拼成 Markdown → 调用 `create_note(note_type="manual")` 保存为结构化笔记 | 点导出 → 我的笔记中出现一篇整合了整棵树内容的笔记 |
| 6 | 拖拽排序 | 支持拖拽节点到不同父节点下（改 `metadata.parentId`）——如实现复杂可延后到 v1.1 | 拖拽 → 节点归属变化 → 刷新后仍在 |

**难度点**：
- 树结构的数据存储：用 notes 表的 `metadata` JSON 字段存 `parentId`，不需要新表。根节点 `parentId=null`，子节点指向父节点 note_id。
- 递归删除子节点：删除节点时，前端递归收集所有子孙节点 ID，批量调 DELETE 接口。

## 四、阶段 2：三大学习模式（第 3-4 周）

### 2-1 思考模式

**当前状态**：后端完整，前端 557 行。AI Coach 使用写死的 `COACH_PROMPTS`，与笔记内容无关。

**目标**：AI 根据笔记内容动态追问，多轮对话有记忆，修订建议可一键应用。

| # | 任务 | 具体做什么 | 验收方式 |
|---|------|-----------|---------|
| 1 | 动态追问 | 后端新增 `POST /thinking/sessions/{id}/generate-prompt`：读取笔记前 500 字 → 调 LLM 生成针对性追问；前端删掉 `COACH_PROMPTS` 数组，改用接口获取 | 数学笔记触发数学追问，英语笔记触发英语追问，不再是统一文案 |
| 2 | 对话记忆 | `add_prompt` 方法中把最近 10 条历史对话传给 LLM；超过 10 条时压缩为摘要 | 第 3 轮追问明显基于前 2 轮内容，AI 不会重复问同样的问题 |
| 3 | 修订建议应用 | 后端 `suggested_blocks` 改为结构化数据（含 `action: replace/insert` + `original_block_id`）；前端渲染"修订预览卡片"：原文（红）+ AI 版（绿）+「应用」按钮 | AI 指出错误 → 显示对比卡片 → 点应用 → 笔记内容被替换 |
| 4 | 界面状态补全 | 空白状态（无会话→引导卡片）、加载中（骨架屏）、错误（重试按钮） | 三种状态均有对应 UI |

### 2-2 记忆模式

**当前状态**：后端完整（含 SM-2 间隔重复算法），前端 317 行。AI 卡片生成已接入。

**目标**：卡片质量可靠，复习体验流畅，记忆库可按课程分组。

| # | 任务 | 具体做什么 | 验收方式 |
|---|------|-----------|---------|
| 1 | 卡片生成质量 | 调优 LLM prompt：要求每张卡片聚焦一个概念、Q 要具体（不泛泛）、A 要简洁准确；生成后前端展示预览，用户可删除不满意的卡片 | 从一篇 1000 字笔记生成 5 张卡片 → 每张 Q 具体、A 准确 |
| 2 | 复习交互 | 翻转动画用 CSS `transform: rotateY(180deg)` + `perspective`；四个难度按钮颜色区分（绿蓝紫红）并有点击反馈 | 点击卡片翻转 → 无闪烁；选难度 → 按钮有视觉反馈 |
| 3 | 记忆库分组 | 按课程筛选卡片；显示每个课程的卡片数量和复习进度 | 切换课程 → 卡片列表更新；看到"高等数学 12/20 已掌握" |
| 4 | 到期提醒 | Dashboard 中显示到期卡片数量；记忆库中标红即将到期的卡片 | 有到期卡片时，记忆模式入口有红色角标 |

### 2-3 费曼模式

**当前状态**：后端完整（含 DeepSeek 对话），前端 359 行。

**目标**：LLM 对话稳定可控，评估结果清晰，对话可保存。

| # | 任务 | 具体做什么 | 验收方式 |
|---|------|-----------|---------|
| 1 | 对话稳定 | System prompt 增加格式约束："每次只追问一个问题""回复 60-150 字""不直接给出答案"；temperature 保持 0.7 | 连续 5 轮对话 AI 不跑题、不突然结束 |
| 2 | 评估展示 | 5 轮后 AI 返回 JSON 评估（scores/gaps/tips）→ 前端渲染为表格或简单卡片；评分维度：逻辑/准确度/清晰度/举例/应答 | 评估结果包含 5 个维度的分数 + 2 条漏洞 + 2 条建议 |
| 3 | 总结保存 | 对话结束后，前端提供「保存总结到笔记」按钮 → 调 `create_note(note_type="feynman")` 保存 AI 评估内容 | 点保存 → 我的笔记中出现来源标记"费曼"的笔记 |
| 4 | 概念关联 | 费曼对话关联到具体的 note 或 concept；从知识图谱中选择概念发起对话（如果知识图谱暂不可用，至少支持从笔记发起） | 从笔记进入费曼 → 对话关联到该笔记 |

### 阶段 2 用户验收场景

> **场景 D — 思考模式：深度理解**
>
> 小明在"我的笔记"里看到之前导入的"TCP 三次握手"笔记。他觉得有些概念理解得不够深，点击笔记右上角「开始思考」。
>
> 页面切换到思考模式。AI 没有说"请解释什么是极限"这种通用废话，而是根据他笔记里"三次握手中 SYN 和 ACK 标志位的作用"生成追问："你说第二次握手时服务器的 SYN+ACK 确认了客户端的发送能力——那第三次握手确认了什么？如果省略第三次握手会有什么问题？"
>
> 小明在输入框里打字回答。AI 收到后，追问道："你提到了历史连接的问题。假设一个旧的 SYN 包在网络中延迟了 2 分钟才到达服务器，而客户端已经关闭了——服务器会怎么处理？"——追问明显比第一轮更深了。
>
> 三轮对话后，AI 说："你的理解不错。但我注意到你笔记里'服务端 SYN+ACK 确认了双方能力'这个表述不太准确，实际只确认了客户端→服务器的单向能力。要我帮你修正吗？"小明点"好"。
>

## 五、阶段 3：格式对齐 & 模块互通（第 5-6 周）

**核心问题**：四个模式写入笔记的格式不一致，导致在"我的笔记"中渲染异常。

### 统一笔记块格式规范

所有模块写入 `note_blocks` 表时，遵循此规范：

```json
{
  "blockType": "paragraph | heading | quote | code | table | ai_summary | thinking | memory_cards",
  "content": "文本内容",
  "position": 0,
  "metadata": {
    "level": 1,                  // 仅 heading
    "source": "thinking | memory | feynman | quick_timeline | resource_import"
  }
}
```

### 详细任务

| # | 任务 | 具体做什么 | 涉及文件 |
|---|------|-----------|---------|
| 1 | 制定格式规范 | 把上面的 JSON 规范写成 1 页文档，发群公告；各开发者在自己的模块中按规范写入 | 群文档 |
| 2 | 思考→笔记 | `add_revision_suggestion` 的 `suggested_blocks` 内容写入 note_blocks 时，`blockType` 使用 `thinking`，`metadata.source = "thinking"` | `thinking/service.py` |
| 3 | 记忆→笔记 | 记忆卡片以引用块形式写入：`blockType: quote`，`content: "Q: xxx\nA: yyy"`，`metadata.source: "memory"` | `memory/routes.py` 的 generate 逻辑 |
| 4 | 费曼→笔记 | 评估总结以 heading + paragraph 写入：`blockType: heading`（标题"费曼评估"）+ `blockType: paragraph`（评估内容），`metadata.source: "feynman"` | `feynman/service.py` |
| 5 | 速记(时间流)→笔记 | 速记 AI 生成的内容，`note_type` 传 `quick_timeline`，确保在笔记管理中正确分组 | `quick-notes/QuickNotes.jsx` |

| 7 | TipTap 渲染适配 | `tiptap-converter.js` 的 `blockToTipTapNode` 支持 `thinking`/`memory_cards`/`ai_summary` 三种自定义 blockType 的渲染（带颜色背景和来源标记） | `tiptap-converter.js` |
| 8 | 全链路走通 | 逐链路验证：速记(时间流)→笔记→思考→记忆→费曼，速记(时间树)→笔记→思考→记忆→费曼，每个环节产生的笔记内容在"我的笔记"中都能正确显示 | 手动逐环节测试 |

> **任务 3：用思考模式深入理解**
> 小刘打开刚保存的笔记 → 点击「开始思考」→ AI 根据笔记内容追问"你说操作系统管理四大资源，CPU 是其中最重要的——为什么不是内存？"（不再是通用模板）→ 小刘回答 → AI 继续追问 → 三轮后满意 → 结束思考。
>
> **任务 4：分享到社区**
> 小刘觉得这篇笔记整理得不错 → 右键笔记 → 点「分享到社区」→ 切换到社区 → 看到自己分享的帖子出现在列表顶部 → 切换到另一个浏览器标签（用另一个测试账号登录）→ 看到小刘的帖子 → 点赞 + 评论"好文！"→ 小刘回到自己的页面刷新 → 点赞数变为 1，评论出现。
>
> **任务 5：自由探索**
> 小刘自由点击各功能页面，没有遇到白屏、报错、按钮无响应的情况。所有页面加载时间 < 3 秒。
>
> **测试总结**：小刘填写一份简单反馈表，记录体验打分（1-5 分）和建议。主要反馈：录音转写偶尔有错字（"进程"识别为"进行"）、记忆卡翻转动画有点快。团队记录这些问题，评估是否阻塞上线。
