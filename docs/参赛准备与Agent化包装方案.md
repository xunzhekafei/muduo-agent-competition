## 五、把木铎笔记包装成「AI Agent 智能体」：现状差距与改造路线

### 5.1 现状诊断：木铎现在是什么？

木铎笔记目前是 **「AI 辅助学习平台」**，不是真正意义上的 **「AI Agent」**：

| 维度 | AI Agent 应有 | 木铎现状 | 差距 |
|------|--------------|---------|------|
| 工具调用 | 能调用外部工具/API 完成任务 | LLM 只做单轮「生成」，后端功能靠前端按钮触发 | 🔴 缺 Tool Calling |
| 自主编排 | 多步规划、任务分解、循环决策（ReAct） | 无编排层，一次请求一次响应 | 🔴 缺 Agent Loop |
| 记忆/状态 | 记住用户偏好与历史，持续上下文 | 有 SM-2 掌握度，但未作为 Agent 上下文 | 🟡 缺 Agent Memory |
| 知识库 | 语义检索（RAG）支撑回答 | Embedding 是 Mock，无向量检索 | 🔴 缺 RAG |
| 主动性 | 能主动规划学习、提醒、建议 | 被动等待用户操作 | 🟡 缺规划能力 |

**一句话结论**：木铎已经有很好的「工具」和「学习科学方法论」，缺的是把这些工具**交给一个能自主决策的 Agent 去调度**的那一层。

### 5.2 包装定位：教育领域「AI 学习导师智能体」

建议参赛定位：

> **「木铎——AI 学习导师智能体」**：面向大学生/考研学生的真实学习场景，一个能**听懂需求 → 自主规划学习路径 → 调用笔记/思考/记忆/费曼等工具 → 记住你的掌握度 → 持续陪伴你完成学习闭环**的教育领域 AI Agent。

**契合大赛的三个卖点：**

1. **真实业务场景**：记笔记、理解、复习、输出，是每个学生每天的真实痛点。
2. **跨学科视角**：木铎天然融合了教育学与认知科学理论——**费曼学习法**（以教代学）、**苏格拉底式提问**（深度思考）、**间隔重复 SM-2 / 记忆曲线**（科学复习）、**知识图谱**（结构化知识）。这正是大赛「（四）创新性与跨学科视角」要的东西。
3. **可验证的智能体交互**：Agent 与用户多轮对话、调用多个工具完成一次完整学习任务，具备可演示性。

### 5.3 改造步骤（6 步）

#### Step 1 —— 重新叙事：从「工具」到「Agent」

- 把产品主页/README 的核心话术从「AI 辅助学习平台」改为「AI 学习导师智能体」。
- 明确 Agent 的 **角色（Persona）**、**目标**、**能力边界**。

#### Step 2 —— 把功能模块抽象为 Agent 工具（Tools）

把现有后端能力包装成 LLM 可调用的工具，每个工具带 JSON Schema 描述：

| 工具名 | 功能 | 对应现有模块 |
|--------|------|-------------|
| `create_note` / `search_notes` | 记笔记 / 检索笔记 | `notes` |
| `parse_resource` | PDF/网页 → 结构化笔记 | `resource_notes` |
| `ask_thinking_question` | 苏格拉底式追问 | `thinking` |
| `generate_memory_cards` | 生成记忆卡片 | `memory` |
| `schedule_review` | SM-2 间隔重复排期 | `memory` |
| `run_feynman` / `evaluate_feynman` | 费曼练习 / 评估 | `feynman` |
| `get_mastery` | 查询掌握度画像 | `dashboard` |
| `search_knowledge` | 知识图谱/向量检索 | `knowledge_graph` + RAG |

#### Step 3 —— 引入 Agent 编排层（核心改造）

- 在 `integrations/llm.py` 的 `LLMProvider` 协议上扩展 **`generate_with_tools(messages, tools)`**。
- 选型：DeepSeek 支持 Function Calling；也可接入 DashScope 通义千问（`resource_notes/qwen_client.py` 已有通义调用基础）。
- 新增 `backend/app/agent/` 模块，实现标准 **ReAct / Tool 循环**：
  ```
  用户意图 → LLM 规划（选择工具+参数）→ 执行工具 → 观察结果 → LLM 再规划 → ... → 输出最终答复
  ```
- 关键代码产物：`orchestrator.py`（循环编排）、`tool_registry.py`（工具注册表）、`memory.py`（记忆管理）。

#### Step 4 —— 补齐记忆与状态（Memory）

- **短期记忆**：多轮对话上下文（thinking/feynman 已有基础，需统一到 Agent 会话）。
- **长期记忆**：把用户的掌握度、复习记录、易错概念、学习目标持久化，作为 Agent 每次调用的系统上下文注入。
- 实现「Agent 记得你上次学到哪、哪里薄弱、下一步该复习什么」。

#### Step 5 —— 构建知识库（RAG）

- 用真实 Embedding 服务（如 DashScope 文本向量）替换 `MockEmbeddingProvider`。
- 笔记分块 → 向量化 → 存入向量库（MVP 可用 SQLite + 余弦相似度起步）。
- Agent 回答/出题时先检索相关笔记作为上下文，实现「基于你自己的笔记来教你」。

#### Step 6 —— 提示词工程（Prompt Engineering）

- 设计**系统提示词**：角色（学习导师）+ 目标 + 工具使用规范 + 输出格式约束。
- 为每个工具写清晰的 description 和触发条件（这直接决定 Agent 会不会正确调用工具）。
- **准备 ≥3 个可展示的提示词设计示例**（对应附件1 PPT「提示词设计截图」要求），例如：
  1. 学习目标拆解提示词（把大目标拆成每日任务）
  2. 复习规划提示词（根据记忆曲线安排今天复习内容）
  3. 费曼讲解评估提示词（评分维度 + 漏洞 + 建议）

### 5.4 改造路线与附件1 PPT 章节的映射

| PPT 章节 | 对应改造产出 |
|---------|-------------|
| （一）作品介绍 | Agent 定位、叙事、价值主张 |
| （二）数据收集与处理 | 数据来源（课程/教材/用户笔记）、知识库构建（RAG）、预处理流程图（含 Agent 用途） |
| （三）模型与流程 | 模型选择（DeepSeek/通义 + Function Calling）、Agent 编排设计（ReAct 思维导图）、实验验证 |
| （四）创新性与跨学科 | 创新点（工具化学习闭环 + 主动学习规划）、跨学科（教育学 × 认知科学 × AI） |
| （五）应用结果与建议 | 学习效果数据、Agent 优化建议、数据安全风险与应对 |
| （六）应用演示截图 | 多轮对话截图、3+ 提示词截图、工具调用截图 |

## 八、风险与注意事项

1. **时间风险**：官方作品提交截止已过，须立即与本校校赛承办单位确认校赛截止时间与报送方式。

5. **真实性与可验证性**：大赛强调「可验证智能体交互能力」，PPT 里要有**真实的对话截图、工具调用记录、实验数据**，避免只有概念没有落地。

> **现有后端能力不变 → 抽象成 8 个 Tool → 加一个 ReAct 编排层 → 接 Function Calling 大模型 → 补 Embedding/RAG 与长期记忆 → 换一套「学习导师 Agent」的叙事 → 录 6 分钟视频 + 20 页 PPT 参赛。**
