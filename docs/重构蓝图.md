# 木铎 2.0 重构蓝图

> 目标：把「对话式 Agent + 15 个旧工具页」两套身份，融合成一个**独立、完整、一致**的产品。
> 原则：借鉴原项目的思路（学习中枢 / 速记 / 思考 / 记忆 / 费曼 / 笔记 / 社区），但不是简单拼图。

---

## 0. 现状诊断：为什么「脱节」

| 维度 | 对话页（新） | 工具页（旧） |
| --- | --- | --- |
| 视觉 | 中性灰 + 墨绿 `#10A37F` | 荧光绿 `#C7F36B` + 紫/蓝/薄荷 |
| 结构 | 会话栏 + 居中窄列 | 各自为政的仪表盘 |
| 状态 | 打字态、错误提示 | 各写各的 loading/empty/error |
| 数据 | 走 `agent/chat` | 各自 API + mock 降级 |
| 关系 | 不知道工具存在 | 不知道对话存在 |

**结论**：不是「再改改样式」能解决，需要重新定义产品心智 + 一套统一的设计系统 + 统一的模块规范 + 双向的「对话 ↔ 工具」连接。

## 1. 产品心智：对话为中枢，工具为画布

**一句话**：木铎是一个「会自己查笔记、安排复习的 AI 学习伙伴」，对话是它的嘴，工具是它的手。

- **对话（/agent）** 是常驻中枢，永远可达。
- **工具** 是一等公民的结构化工作区，与对话**双向连接**：
  - 工具 → 对话：任何工具产物都可「问 AI」（带上当前笔记/卡片/课程上下文，跳回对话）。
  - 对话 → 工具：Agent 的回复里可深链到工具（打开某篇笔记、某套卡片）。

这样工具不是「另一个 app」，而是「对话的延伸」。

## 3. 设计系统（统一视觉语言）

### 3.1 设计令牌（tokens）

- **主色** `brand`：`#10A37F`（500）/ `#0D8B6C`（600）/ `#0B7A5E`（700），浅底 `#EAF6F2`
- **中性色**：`ink` 文字层级（900/600/500/400/300），`surface`（page 白 / raised / sunken 灰），`line` 分割线
- **语义色**：`success` 绿、`warning` 橙、`danger` 红
- **数据色**（图表/分类）：一套克制的 categorical 色板，替代旧的荧光绿/紫/蓝/薄荷

### 3.2 组件原语（`src/shared/ui/`）

所有模块只用这些原语，不再手写内联颜色和重复的 loading/empty：

- `Icon` — SVG 图标包装（path + 尺寸 + 线宽）
- `Button` — 变体（primary/secondary/ghost/danger）+ 尺寸 + loading
- `Card` / `Panel` — 容器
- `PageHeader` — 模块身份（图标 + 名称 + 一句话说明 + 主操作）
- `Stat` — 指标展示
- `Badge` / `Progress` — 状态与进度
- `EmptyState` / `ErrorState` / `Skeleton` / `Loading` — 统一的三态

## 4. 模块规范（不是拼图的关键）

每个工具模块遵守同一骨架：

```
features/<name>/
  <Name>Module.jsx      模块入口：PageHeader + 数据编排 + 状态
  components/           模块私有组件（用 shared/ui 原语）
```

每个模块统一具备：

1. **PageHeader** —— 图标 + 名称 + 一句话说明 + 主操作按钮
2. **三态** —— Skeleton（加载）→ EmptyState（无数据）→ 内容；ErrorState（失败可重试）
3. **数据来源** —— 走 `api/<name>.js`，失败自动降级 mock（应用永远完整可用）
4. **「问 AI」入口** —— 产物可一键带回对话（带上下文）

## 5. 能力层 / API 抽象（给「新 API」留的缝）

### 5.1 后端（已有，`app/integrations/registry.py`）

Provider 抽象已存在：`LLM / OCR / ASR / Embedding / Storage` 各有一个接口 + mock 实现。

**接入新 LLM API 的步骤**（留空，等你的新 API）：
1. 在 `app/integrations/llm.py` 新增 `XxxProvider`，实现 `LLMProvider` 协议（`generate` + `generate_with_tools` + 流式）
2. 在 `registry.py` 的 `SUPPORTED_LLM_PROVIDERS` 注册名字
3. 在 `app/core/config.py` 加对应配置项
4. `.env` 切 `LLM_PROVIDER=xxx`

### 5.2 前端（已有，`api/*.js` 的 mock 降级）

- 每个领域 API 客户端都有 mock 降级，**后端没接好时前端依然完整**
- 待办：新增 `GET /system/capabilities`，前端据此知道「哪些能力是 mock / 哪些是真的」，UI 优雅降级
