# 前端目录结构说明

前端目录遵循项目根目录 `BUILD.md` 中定义的目标架构。当前整理的重点是先建立清晰边界，后续再逐步把页面中的业务逻辑、mock 数据和接口调用拆到对应目录中。

## 目录职责

- `app/`：应用入口、路由注册、全局 Provider 等应用级初始化代码。
- `layouts/`：页面外壳组件，例如侧边栏、顶部栏、主布局。
- `pages/`：路由页面入口，只负责组合业务模块，尽量保持轻量。
- `features/`：业务功能模块，例如学习中枢、资源转笔记、速记、笔记管理、思考、记忆、费曼、共享社区、系统设置。
- `api/`：前端请求封装和接口方法，页面和业务组件不应直接调用 `fetch`。
- `mocks/`：mock 数据和 mock 服务，数据结构应尽量和后端接口契约保持一致。
- `shared/`：跨业务复用的组件、hooks、工具函数、常量。
- `styles/`：全局样式和 Tailwind 入口样式。

## 开发规则

- `pages/` 里的文件应该主要负责路由级组合，不承载大量业务逻辑。
- 长期使用的 mock 数据放在 `mocks/`，不要继续写在页面组件里。
- 后端请求统一放在 `api/`，不要在页面或组件中散落请求逻辑。
- 只属于某个业务模块的代码放在对应的 `features/*` 目录中。
- 只有能被多个业务模块复用的代码，才放进 `shared/`。
- 新增接口前，优先同步项目根目录 `contracts/` 中的接口约定。
